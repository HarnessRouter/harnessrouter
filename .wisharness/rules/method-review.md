# 需求与工程双维评审

评审、接收反馈或交付前自查时使用；通用约束见 [core](core.md)，不把开发重构移到评审阶段。

- 明确需求、比较基线和所评版本。工作区评审覆盖暂存、未暂存及相关未跟踪文件，不能漏掉未提交改动。
- 分别核对需求符合度与工程质量；没有可核实需求时，需求符合度标未验证，工程检查可继续。问题给出位置、依据和影响，区分硬性缺陷与设计建议。
- 自查不冒充独立评审，本地结果不替代必需 CI 或平台审批；委派遵循已有授权。
- 收到评审意见先核对版本、需求和代码，过期或不适用建议说明依据；未决产品语义按需求方法由 Agent 判断，仅缺少无法自行获取的关键上下文时暂停依赖项并询问。
- 修复后重新验证受影响项，证据对应最终相关代码状态；保留未解决项，不把建议当成已完成修复。
