# 实施方案

- 行为、边界与验收依据：`spec.md`；任务、模板、WorkflowRevision 和 Run 的保存语义引用 `docs/changes/CHG-task-centric-workflow/spec.md#版本关系与保存边界`。
- 执行记录位置：`change-record.yaml`。

## 方案与依赖

- 复用 `client/src/app-api.ts` 的任务列表、Run 启动、Run 详情和 SSE API；新增纯函数负责多 Run 状态聚合和协调摘要。
- 新增 `SuperAgentCoordinator` 页面并接入现有导航；协调层保存的仅是当前页面的订阅与选中状态，不保存任务权威数据。
- 复用任务工作台的任务/模板创建和编辑入口，避免重复实现保存边界。
- 协调页复用 `Templates` 画布设计器，以独立任务/模板保存按钮调用已有 API；不把手工拆词当成智能生成。无新增模型调用或凭据。任务创建返回已保存版本后才可分发。
- 每个 Run 使用独立 `watchCoordinatorRun` 观察器：SSE 中断后有界退避只读恢复，读到活动运行后重连；等待人工/暂停时只读轮询，外部决定后恢复流，终态和权限失效停止；按 Run ID 过滤迟到事件。
- 页级协调状态在模块导航时保留；用户/工作区变更重新挂载观察器并丢弃旧请求。任务列表按 20 条按需追加；刷新保留已监控历史，使用新读取的服务端快照覆盖旧快照。

## 实施与验证

| 步骤 | 改动与依赖 | 对应验收及验证方式 |
| --- | --- | --- |
| 1 | 为多 Run 聚合、进度、状态摘要和失败隔离建立单元测试 | `client/tests/super-agent-coordinator.test.mjs`，先 Red 后 Green |
| 2 | 增加协调页 API 订阅管理、批量分发、断线轮询和结果汇报 | TypeScript 检查、API 单元测试、受控浏览器 E2E |
| 3 | 接入导航和任务/模板跳转，补齐桌面/移动视觉状态 | Playwright 协调页用例、截图与无溢出检查 |
| 4 | 复核保存边界、Cloud 产品契约和现有任务工作台回归 | `npm test`、`npm run typecheck`、目标 Playwright 回归、`git diff --check` |

## 恢复与收尾

- 本次无数据库迁移和外部数据写入；回滚只需移除协调页、导航入口及其测试/文档，不影响既有任务和运行记录。
- SSE 与轮询均为只读恢复；分发请求使用每个任务独立幂等键，失败时保留已启动 Run 的状态。
