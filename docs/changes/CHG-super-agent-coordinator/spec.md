# 行为说明

- 已有需求、设计或契约引用：用户要求在 client 侧增加一个不执行具体工作的 Super Agent，用于向各 Agent 分发任务、实时监控多个任务并汇报结果；任务关系与保存边界遵循 `docs/changes/CHG-task-centric-workflow/spec.md#版本关系与保存边界`。
- 实施方案：`plan.md`。

## 目标行为

- 用户进入“协调 Agent”后，可以选择当前工作区中已经保存工作流的任务，批量启动其 Run，并在同一页面同时查看多个 Run 的实时状态、节点进度、等待人工处理、失败和最终结果。
- 协调 Agent 只负责分发请求、订阅 `/runs/{run_id}/events`、聚合服务端状态和生成面向用户的状态简报；它不作为 Workflow 节点，不调用 Gateway，不自行推进 Run 状态，也不把本地草稿当作可执行版本。
- 用户可以在协调页用已有画布设计任务/模板方案并显式保存，也可进入既有工作台；保存任务与保存模板是独立操作，只有服务端返回的已保存 WorkflowRevision 才能被分发。已完成任务需要在工作台重新打开后再运行。
- 协调页支持暂停、继续和取消运行；人工门控由用户在运行详情作出决定，不自动代替用户选择。多任务监控在切换到任务/模板工作台时继续，登出或切换工作区时清空并关闭旧订阅。

## 边界与非目标

- 同一任务仍遵循后端“最多一个活动 Run”、幂等键和状态机约束；批量分发遇到单任务失败时保留其他任务的成功启动结果，并逐项报告错误。
- SSE 中断时保留最近一次服务端快照，并对该 Run 使用只读轮询恢复；刷新或切换页面后重新从服务端读取，不以协调页内存作为权威状态。
- 列表每批 20 条，用户点击加载更多才读取后续页；监控范围明确为当前已加载任务的最近运行，不宣称监控未加载任务。每项运行订阅按 Run ID 隔离，旧 Run 事件不能覆盖同任务的新 Run。
- 本次不新增 Super Agent 后端模型、Gateway 执行协议、Team/权限模型、外部队列、后台调度器或自然语言自动改写工作流。

## 验收

- 协调页显示多个已选任务，批量启动后为每个成功启动的任务展示独立 Run、状态、节点完成数和实时事件；不同 Run 的状态不能串用。
- 运行中、等待人工、完成、失败和取消状态均使用现有 Task/Run 状态语义；完成后展示最终报告节点或最近可用输出摘要，并提供返回任务/运行详情入口。
- 任一 Run 的 SSE 断开时，其他 Run 继续实时更新；该 Run 显示恢复状态并通过 `GET /runs/{id}` 轮询，恢复或终态后停止轮询。
- 未保存任务不能被协调页直接启动；协调页只能从服务端返回的任务记录调用运行接口，创建任务/模板入口跳转到既有工作台。
- 1440×900 和 390×844 下协调页可用，列表、状态、错误、加载和空状态可读，无页面横向溢出；协调页不显示 Cloud 部署、上传、余额、密钥或 hosted provider 入口。
