# UI 视觉契约

- 设计来源：用户确认的任务模块信息架构、三段式任务详情示意（2026-11-16）、现有 `client/src/main.tsx` 画布和 `client/src/styles.css`。
- 目标页面：任务列表、`/tasks/:id` 任务详情、模板库和模板编辑器。
- 目标视口：Chromium 桌面至少 1280×800；移动 Chromium 至少 390×844。

## 页面结构

- 任务列表显示标题、Task 状态、最近 Run、更新时间、失败/等待提示和创建入口；空状态提供空白创建与模板创建。
- 任务详情顶部显示任务名称、Task 状态、运行/暂停/继续/取消、保存模板、重新打开和归档操作。
- 中间区域以画布为主，右侧是可调整宽度的节点检查器；底部是可折叠运行时间线。
- 检查器显示节点配置、输入来源、NodeRun 状态、输出、错误、重试、跳过和采用结果操作。
- 运行区显示 Run 状态、节点状态、阶段时间、尝试次数、人工等待、过期标记和恢复提示。

## 交互与可访问性

- client 的按钮状态由 API 返回的 Task/Run/NodeRun 状态决定；前端不自行完成状态转换。
- 活动 Run 中可编辑布局、视图状态和任务描述；Agent、提示词、模型、工具、依赖、输入引用和门控配置锁定，并说明需暂停或取消运行后修改。
- 人工等待时突出显示候选结果、已选结果和“继续”；候选结果与当前采用结果使用文字和状态标签区分，不能只靠颜色。
- 运行中的节点提供可读状态、Agent 名称、输入来源和错误信息；敏感值显示脱敏文本。
- 任务详情支持加载、空、失败、保存冲突、运行中断、权限不足和恢复状态；页面刷新后从 API 恢复，不依赖内存状态。
- 移动端将检查器和运行区改为抽屉或底部面板，工具栏允许换行；画布节点标题截断时提供完整可访问名称。

## 验收

- 用角色、可访问名称和可见文本定位关键控件，不用脆弱的 CSS 选择器。
- 桌面检查三段区域、画布缩放/拖拽/连线、检查器宽度和运行区折叠。
- 移动检查任务状态、节点选择、继续、失败提示和返回任务列表均可操作。
- 检查 `/tasks/:id` 直接访问和刷新不产生 404。
