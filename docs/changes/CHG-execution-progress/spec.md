# 行为说明

- 需求来源：2026-11-19 用户要求一起修复对话与编排执行过程不可见的问题。
- 相关契约：CHG-chat-reply-details/spec.md、CHG-task-centric-workflow/spec.md（版本关系与保存边界）。
- 实施方案：plan.md。

## 目标行为

对话与工作流 Agent 节点在执行中展示 Gateway 实际返回的增量文本、公开摘要与工具名称/状态。刷新后恢复当前进度；结束、失败和取消后保留已收到的过程。不同节点、尝试和对话互相隔离。Runner 容器为每次执行输出可关联 Runner、会话和 turn 的开始、定时进度与终态日志。

## 边界与非目标

复用现有 Cookie 权限、SSE 和数据库；进度不进入模板或工作流定义，也不作为下游的成功输出。不展示原始工具参数或内部思考；持久化前及返回前脱敏，限制文本和步骤大小。容器日志只含关联标识、状态、耗时和事件计数，不含提示词、正文、工具参数、凭据和异常原文。历史无过程数据时不伪造。保留既有未提交修改，不恢复 Cloud 入口，不自动重放执行或重启生产容器。

## 验收

- 对话订阅早于请求启动时不会被旧 idle/completed 快照提前关闭；中断后重连，刷新活动会话恢复当前文本和详情。
- 两个并行节点在完成前可独立读取进度；失败/取消后保留已收到内容，迟到回调不能覆盖终态；成功输出保持原契约。
- 节点属性面板显示实时过程，桌面与 390px 视口可读，长文本不横向溢出。
- Runner 日志覆盖正常、失败和异常退出，长任务每 30 秒有计数进度；不泄露测试 canary，不改变路由清理与执行语义。
- 单元、API/SQLite 集成和受控 HTTP Gateway 浏览器 E2E 验证上述边界；真实模型与未执行平台明确标注限制。
- 任务/运行深链详情独立于辅助列表读取；辅助列表失败保留详情并标明具体失败范围，可重试。鉴权失败继续走登录恢复，不吞掉 401；工作区权限检查不降级。
- 部署验证须检查 4173 前端实际代理的 4010 服务与只读 Run #8，明确区别于 4020/4022 的受控模型 E2E。无实际浏览器证据不得宣称真实入口已验证。
